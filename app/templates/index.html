The GRC Framework Triad

Three distinct methodologies with overlapping control objectives. Understanding their fundamental differences is essential for effective security governance.

AICPA Standard

SOC 2 (TSC)

Attestation report designed for technology and cloud service providers storing customer data. Evaluates controls over time.

  • 5 Trust Services Criteria (Security mandatory)
  • Type I (Point-in-time) vs Type II (3-12 mos period)
  • Independent CPA / AICPA firm opinion
International Standard

ISO/IEC 27001:2022

Comprehensive global standard for establishing, implementing, maintaining, and continually improving an Information Security Management System (ISMS).

  • Clauses 4-10 (ISMS Lifecycle & PDCA)
  • Annex A: 93 controls in 4 themes (Org, People, Physical, Tech)
  • Formal accredited Certification (3-year cycle)
NIST Guidance (Voluntary)

NIST CSF 2.0

Outcome-driven, flexible risk management taxonomy published by the U.S. National Institute of Standards and Technology.

  • 6 Functions: GOVERN, Identify, Protect, Detect, Respond, Recover
  • Categories, Subcategories, and Implementation Tiers
  • Voluntary benchmark (No official certification)

Application Architecture & Threat Model

A GRC platform holds the most sensitive risk and control gap findings of an organization. Our system architecture enforces defense-in-depth across the entire lifecycle.

Multi-Layer Architecture

Presentation: Semantic HTML5, Jinja2, Vanilla CSS with custom design tokens, JS micro-interactions.
API / Application: FastAPI (async ASGI), Pydantic v2 schemas, Dependency Injection, RBAC middleware.
Persistence: SQLAlchemy 2.x Declarative Models, Alembic migrations, Multi-tenant organization isolation.
Storage: Isolated file vault, SHA-256 integrity checks, MIME-type and extension validation.

STRIDE Threat Matrix (GRC Platform)

Spoofing: User or auditor impersonation.
→ Mitigated via bcrypt password hashing, secure HttpOnly SameSite session cookies, JWT validation.
Tampering: Manipulating control test results or evidence.
→ Mitigated via SHA-256 cryptographic hashes for all evidence files and append-only audit event logs.
Repudiation: User denies closing a risk or approving a test.
→ Mitigated via structured security event logging recording actor, timestamp, IP, and changes.
Information Disclosure: Cross-organization tenant leakage.
→ Mitigated via strict organization-level scoping enforced in every DB query and gated file streaming.
Elevation of Privilege: Analyst executing admin actions.
→ Mitigated via 5-tier server-side RBAC dependencies evaluated per endpoint.
